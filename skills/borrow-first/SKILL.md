# borrow-first — 借鉴优先

**原则：最好的代码是你不必写的代码。** 动手写新东西前，先证明"没有值得借鉴的现有方案"；
裁决要有证据，借鉴要讲出处。（流程：查 → 读 → 判 → 固化）

**启用纪律**：见 using-superpowers 的 1% 规则——本技能由"实现 X / 选型 / 有没有现成的"
等任务触发；作为「研究→计划→编码」的研究闸门，在 brainstorming / writing-plans 之前跑
Step 0-3，执行中发现新需求点回到 Step 1，不硬写。

---

## Step 0 — 说清需求（先于任何工具调用）

用**普通文字**（不是工具参数）写 2-3 句：**要什么**（具体功能，不是口号）／**用什么**
（语言/框架/环境）／**约束**（已有依赖、性能、许可证）。让用户能先纠偏，也留审计记录。

## Step 1 — 按优先级搜（命中即停）

1. **本机已有代码**：`grep`/`rg` 相关模块和测试——东西可能已存在
2. **包注册表**：npm / PyPI / crates / Go modules
3. **已装能力**：已配置的 MCP、已安装的技能/工具——可能早接好了
4. **GitHub/OSS**：代码搜索现有开源实现、模板
5. **官方文档兜底**（框架/库决策）：官方文档 > 官方博客/变更日志 > 标准参考 > 兼容性表；
   Stack Overflow、教程、AI 摘要只当线索，不当引用

决策时查**实时文档**，不信记忆里的包信息——推荐会过期。

## Step 2 — 读透候选（意图锚定 + 费曼门控）

- **意图与代码成对读**：每段先问"它为什么存在"，只看形状是仪式性模仿，只看意图是空想
- **费曼门控**：读完后能用大白话讲清才算懂——讲不清 = 没懂 = 不能借鉴；输出先 TL;DR（≤3 句）
- 参考实现**整篇读完**（方法/边界/错误处理/测试），半懂照抄必出 bug

## Step 3 — 裁决一行（每次必交）

整体评估：功能匹配、维护状态（最后提交/issue 响应）、社区、文档、**许可证**、依赖体积。
散文描述优劣，**不打分**（8/10 是假的精确度）。

**许可证纪律（借鉴/复制二分法）**：借鉴 = 学思路自己重写，无许可负担；复制 = 大段搬代码，
先查许可——MIT/Apache-2.0 可搬但要保留版权头署名，GPL/AGPL 传染闭源先说明，无许可/专有
只借鉴不搬；拿不准按复制处理。

| 裁决 | 何时 | 动作 |
|------|------|------|
| **Adopt** | 完全匹配、维护良好、许可兼容 | 直接用 |
| **Extend** | 基础好、部分匹配 | 装 + 薄包装 |
| **Compose** | 几个弱匹配 | 组合 2-3 个小包 |
| **Build** | 没有合适的 | 自己写，但基于调研 |

```
Verdict: <Adopt|Extend|Compose|Build> — <包名或 custom> — <证据: 星数/最后提交/功能匹配/许可证>
```

只搜不裁决 = 白做。用户说"别查了直接写"也要先记裁决行再动手——跳过调研本身是决策，
要留痕。

## Step 4 — 引用来源 + 固化教训

- 借鉴的关键决策给**全 URL** 出处；查不到明确标 `UNVERIFIED`，诚实比假自信值钱
- 教训 5 分钟内记入 `知识库/踩坑日志.md`（一行一条）——借鉴是复利，日志是本金

---

## 快速 / 完整模式

- **快速（内联）**：单一明显需求——自己几步搜索，直接给裁决行
- **完整（委派）**：需求不平凡——Step 0 后把扫描交给研究子代理，要求返回候选 + 裁决行

## 反模式（红线）

- 跳进代码就写 · 无视已装能力 · 半懂照抄 · 过度包装 · 依赖膨胀
- 只搜不裁决 · 引用二手来源 · 不标 UNVERIFIED · 无视许可证照抄
